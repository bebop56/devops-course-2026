# Заметки по работе с Git в VS Code

## 3 вещи, которые удобны в VS Code:

1. **Визуализация изменений (Diff View).** Очень удобно видеть, какие именно строки были добавлены или удалены, прямо в редакторе, без использования `git diff`. Подсветка изменений помогает быстрее проверить код перед коммитом.

2. **Управление конфликтами слияния (Merge Editor).** В VS Code есть встроенный редактор конфликтов с кнопками «Accept Current», «Accept Incoming» и «Accept Both». Это намного быстрее и нагляднее, чем вручную править маркеры `<<<<<<<` в терминале.

3. **Интерактивный стейджинг (Stage Changes).** Можно выбрать не весь файл целиком, а только конкретные строки или блоки кода (через панель Source Control), чтобы закоммитить только нужную часть изменений.

## 1 вещь, которую удобнее делать в терминале:

1. **Сложные операции с историей (Interactive Rebase, Cherry-pick).** Команды вроде `git rebase -i HEAD~3` или `git cherry-pick <hash>` в терминале выполняются быстрее и дают полный контроль над процессом. В GUI VS Code такие операции либо скрыты, либо реализованы неудобно, и всё равно приходится открывать консоль.
